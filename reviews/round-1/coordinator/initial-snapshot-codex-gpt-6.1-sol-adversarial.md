## Initial assessment

### Findings (most severe first)

1. **P1 — Pair 3 changes the explicitly matched total-volume distribution.** `testbed/world/families.py:522–527`; conflicting design at `testbed/world/DESIGN.md:157–159`; balance check at `testbed/eval/health.py:299–312`. Failure scenario: condition on a group's admitted session count N. In the twin, total consumed credits sum N independent two-event amount draws; at s=1, every session uses the same group draw `(a,b)`, so the total is `N*(a+b)`. Since each uniform 1..4 amount has variance 1.25, the conditional total variance is `2.5*N` in the twin and `2.5*N²` in the abusive family. Repeated sessions also change each account's own total-volume distribution. Thus aggregate volume carries label evidence without comparing timeline order; this conflicts with SPEC §5.1(3)'s explicit matching of total activity volume. This does **not** show an F12 leak: the T tag concerns F12, not F64. The raw evidence is consistent with the consequence: channel pair 3's F64 boosted-tree AUC is `0.8258000000000001`, while its generator-sample raw-credit AUC check passes (`0.47631262500000005`, adjusted test). A raw-variable AUC near 0.5 cannot establish matching distributions: symmetric variance changes can retain AUC 0.5. Fix: resolve this SPEC/design conflict before freezing; preserve the required volume distribution while introducing sequence dependence, or obtain an explicit owner decision narrowing that invariant and the resulting claim. Add a known-answer volume/distribution regression that discriminates the two constructions; don't interpret the current scalar AUC pass as proof of distribution matching.

2. **P1 — Ordinary relative imports bypass the ground-truth boundary test.** `tests/test_ground_truth_boundary.py:68–69` and `:117–126`. Failure scenario: a module in `testbed/pipeline/` adds `from ..eval.labels import open_labels`, imports `Stores`, and returns `open_labels(Stores.under(p)).label`. Python resolves that to the prohibited label reader, but `_imports` records only `eval.labels` because it discards `ImportFrom.level`; the eval guard tests only names beginning `testbed.eval`. This specimen also has no sealed string literal, no prohibited ground-truth import spelling, and attributes only `under` and `label`, so the other static guards pass. A read-only AST reproduction using the actual `_imports` function confirmed that the relative form yields an empty detected eval-import set while the absolute form is caught. Fix: resolve relative imports against the scanned module's package before applying the allowlist, and add negative fixtures for relative imports, including `from ..eval import labels`. No actual source leak was found in the candidate; the defect is in the required enforcement test.

3. **P2 — The second public store opener bypasses the confirmation seal.** `testbed/eval/stores.py:13–22`, compared with `testbed/eval/labels.py:80–81`. Failure scenario: `verify_pair(Stores.under(Path('runs/confirm-example')))` opens the ground-truth engine/session and reads its evaluation receipt regardless of whether M6.md exists or its hashes match. The seal is checked only by `open_labels`; `verify_pair` is a separate existing entry point, used by the smoke test. This violates the explicit rule that confirmation ground-truth stores are opened only by the M6 scorer after freeze, even though this particular path reads provenance rather than labels. Fix: centralize confirmation authorization before **every** ground-truth opener, or restrict/remove this alternate entry point; test that attempting verification cannot open a confirmation store before a valid seal. This is a pre-existing M0 hole exposed by the M1 seal, not an observed opening of real confirmation data during review.

4. **P2 — The null rule substitutes distribution exchangeability for an AUC confidence interval.** `testbed/eval/metrics.py:121–130` and `:147–150`. Failure scenario: positive scores are equiprobable -1/+1, negative scores are always 0, with 40 positives and 160 negatives. Population AUC is exactly 0.5, but the unstudentized label-permutation test assumes the two score distributions are exchangeable. Exact finite combinatorial enumeration gives p=`0.005092447416579459` when 24 positives are +1 (observed AUC 0.6); at Bonferroni `tests=6`, the exact permutation rule rejects for K≤16 or K≥24, occurring with probability `0.26818725105476915` under this AUC=0.5 population. This is not a 95% AUC interval inverted at 0.5. The example has unequal distributions, so it does **not** refute the narrower fair-generator calibration claim; it refutes the advertised equivalence to SPEC's AUC-CI rule. This matters when mechanisms themselves change volume variance (finding 1, also the budget mechanism). Tests currently calibrate exchangeable distributions only. Fix: implement an interval/test valid for the stated AUC estimand, with sparse/tied known-answer coverage, or explicitly resolve the specification to an equality-of-distributions null and stop describing it as an AUC confidence interval. Enumeration used only standard-library arithmetic, no generated worlds or stores.

5. **P2 — World manifests still publish design tags instead of the measured freeze tags.** `testbed/world/generator.py:384`; `testbed/world/families.py:81–84`; `tests/test_generator.py:156`. Failure scenario: any standard world generated by this candidate records pair 1 as F and pair 5 as M, although the frozen measured constants and channel output say pair 1=M and pair 5=F. Every inspected standard-world manifest contains the stale tags. Downstream channel-stratified reporting based on the manifest therefore misclassifies those families. `MEASURED_TAGS` has no indexed consumer; the manifest test explicitly expects `CHANNEL_TAGS`, pinning the wrong behavior. Fix: emit the measured tags as authoritative channel metadata (optionally retain a separately named designed-tag field), and test agreement with the frozen measured tags/channel result.
