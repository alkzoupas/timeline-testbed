Written by the coordinator before any R1 or R2 score, and before any probe is fitted. SPEC §7 (R1,
R2), §7.1 (G2), §6.3, §6.4. Generator `tt-gen-v1`, render `raw-v1` (DECISIONS). Amendments go at

## Before the experiment (AGENTS.md)

1. **Decision it changes.** PASS: M5 runs (R3, LoRA on the 4B; G3). FAIL: the LLM line stops and M7
   writes it up; R1 never rescues a failed G2. LEAK: no pass; find the leak first, report to the owner.
2. **Independent groups per class.** Each gate comparison pools two worlds: per held-out test side,
   the side's two T families give 160 abusive / 640 legitimate groups (320 / 1,280 over both
   sides); each family 80 / 320. The same at *s* = 0.
3. **Full-size smoke test.** `r2 tune` runs the whole route (embed → standardize → L2 logistic per
   held-out fold → primary metric) on the 1,200-unit tuning world, and `g2 --dry-run` loads, aligns
   and checks every gate input without computing a metric. Both are recorded below before scoring.

## R2, the probe

- Candidates: `mean_final`, `mean_16`, `last_final` (SPEC's three). C ∈ {1e-5, 1e-4, …, 1, 10}.
- Fit: StandardScaler, then L2 logistic regression (lbfgs, `max_iter` 10,000), on the training rows
  only; score = decision function. Held-out folds A and B and in-family folds exactly as R0's.
- **Selection, per model, on the tuning world only:** the highest held-out primary metric; ties go
  to the smaller C, then to the earlier candidate. The tuning world is the inner loop of SPEC's
  nested CV and the gate worlds are the outer test; selection uses the gate's own two-fold
  held-out-family split. Its folds train on 600 units, the gate's on 1,200 (accepted). The choice
  and `tune.json`'s sha256 are added below before any gate world is scored.

## G2 (scored once, by `python -m testbed.eval.g2`)

Primary metric (SPEC §6.4) in the held-out regime: per side, the AUC of its T abusive groups
against their twins; the mean of sides A and B. Paired bootstrap: R0's 2,000 resamples within
(side, class), seed 20261033, shared by every rung. F64 scores are recomputed on the same units and
must reproduce M2 (0.462 logistic, 0.517 trees, at *s* = 0.75); otherwise the scorer stops.

For each model *m* ∈ {9b, 4b}:
- **(a) Beats F64 at *s* = 0.75:** both R2*m* − F64 logistic and R2*m* − F64 trees have a lower
  bound > 0, the bound being the 1.25th percentile of the paired resamples (the lower end of a
  two-sided 97.5% interval: SPEC's 95% bound, Bonferroni-adjusted for two models).
- **(b) No signal at *s* = 0:** with the same frozen feature and C, R2*m*'s primary 95% interval
  (2.5th to 97.5th percentile) contains 0.5.

**Verdict:** PASS if some model meets (a) and every model meets (b). LEAK if some model meets (a)
and some model fails (b). FAIL if no model meets (a); any (b) failure is reported with it.
No rescue rule, no re-tuning and no re-draw after a gate number is seen.

## Known risks (stated before results)

- The sweep is paired across *s* (M2 caveat): the *s* = 0 and *s* = 0.75 worlds of a seed share base
  draws, so chance structure repeats. F64 logistic sits below 0.5 on these draws; (a) also needs
  trees (0.517).
- Under no R2 advantage, a model passes (a) with probability ≤ 1.25%; over two models ≤ 2.5%. A fair
  pipeline fails (b) for one model with probability about 5%, so LEAK can fire by chance; it blocks,
  it doesn't fail.

## Reported, not gating

- R2, both models: per family, per channel, pooled, both regimes, recall at FPR 5% and 10%, at
  *s* = 0.75, 0 and 0.5 (secondary); the tuning grid.
- R1: the 9B zero-shot on this prompt; score = expected level over the ten terminated
  `RISK_LEVEL` answers, head in float32; `m1-dev-s0.75-seed1` and `m2-dev-s0.5-seed1` (SPEC's
  one-seed default). The cached-vs-full agreement check on 10 units is recorded before that run.
  Nimble is reported if it runs.
